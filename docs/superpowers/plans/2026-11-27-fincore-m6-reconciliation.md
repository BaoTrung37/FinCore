# FinCore M6 — Reconciliation Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the `internal/modules/reconciliation` module (external bank statement reconciliation via JSON/CSV + internal ledger integrity audit + discrepancy resolution + outbox events + OpenAPI/docs updates).

**Architecture:** Modular Monolith domain module owning 3 PostgreSQL tables (`reconciliation_runs`, `reconciliation_items`, `ledger_audit_runs`) generated with `sqlc`, read-only SQL queries over `payments`, `accounts`, `ledger_transactions`, and `ledger_entries`, pure deterministic matching and CSV parsing packages for fast unit testing, and transactional outbox publishing via the existing `webhook.Event` contract.

**Tech Stack:** Go `1.27+`, `chi/v5`, PostgreSQL 17, `pgx/v5`, `sqlc`, `golang-migrate/migrate/v4`, `encoding/csv`, `log/slog`.

**Spec:** [2026-11-27-fincore-m6-reconciliation-design.md](../specs/2026-11-27-fincore-m6-reconciliation-design.md)

## Global Constraints

- Money values are strictly `int64` minor units (`BIGINT` in PostgreSQL); never `float64`.
- Supported currencies are `VND` and `USD` only (uppercase `CHAR(3)`).
- Strict module boundary: `reconciliation` only writes to `reconciliation_runs`, `reconciliation_items`, and `ledger_audit_runs`; never `UPDATE`/`DELETE`/`INSERT` into `payments`, `accounts`, `ledger_transactions`, or `ledger_entries`.
- All `/api/v1/reconciliation/*` routes require `auth.RequireAuth(tm)` and enforce `user_id` ownership.
- CSV upload requests must be bounded by `http.MaxBytesReader` (1 MiB) and parsed with Go stdlib `encoding/csv`.
- All new tests must pass under `go test -race ./...`; integration tests must skip cleanly if PostgreSQL is unreachable.

## Review Focus

- **Duplicate `external_ref` in bank statement input:** Reject the entire run with `400 DUPLICATE_EXTERNAL_REF` instead of silently overwriting or double-matching a payment.
- **CSV amount formatted as decimal (e.g. `"100.50"`) or non-positive (`"0"`, `"-500"`):** Reject with `400 INVALID_STATEMENT_RECORD` (never truncate floats or accept zero/negative amounts).
- **Resolving an already-matched (`not_applicable`) or non-existent item, or cross-user `run_id`:** Return `400 ITEM_NOT_RESOLVABLE` for matched items and `404 RUN_NOT_FOUND` / `404 ITEM_NOT_FOUND` for missing or other-user resources.
- **`period_end < period_start` or missing/invalid RFC3339 timestamps:** Reject with `400 VALIDATION_ERROR` before touching the database.
- **Empty bank statement (`records: []`) when internal payments exist in the window:** Succeed with `201`, mark all internal payments in the window as `missing_in_bank`, and set run status to `has_discrepancies`.

Write the SQL queries in `internal/modules/reconciliation/queries/reconciliation.sql`:
- `ListPaymentsForReconciliation`: `SELECT id, external_ref, direction, amount, currency, status FROM payments WHERE user_id = $1 AND bank_code = $2 AND currency = $3 AND external_ref IS NOT NULL AND created_at >= $4 AND created_at <= $5 ORDER BY created_at ASC`.
- `ListReconciliationItemsByRun`: filters by `run_id = $1`, optional `match_status` (`sqlc.narg('match_status')::text IS NULL OR match_status = sqlc.narg('match_status')`), optional `resolution_status` (`sqlc.narg('resolution_status')::text IS NULL OR resolution_status = sqlc.narg('resolution_status')`), ordered by `created_at ASC, id ASC`.
- `FindUnbalancedLedgerTransactions`: aggregates `ledger_transactions lt LEFT JOIN ledger_entries le ON le.transaction_id = lt.id GROUP BY lt.id HAVING COUNT(le.id) < 2 OR COUNT(DISTINCT le.currency) > 1 OR COALESCE(SUM(CASE WHEN le.entry_type = 'debit' THEN le.amount ELSE 0 END), 0) != COALESCE(SUM(CASE WHEN le.entry_type = 'credit' THEN le.amount ELSE 0 END), 0)`.
- `FindDriftedAccounts`: compares `a.balance_amount` vs `COALESCE(SUM(CASE WHEN le.entry_type = 'credit' THEN le.amount ELSE -le.amount END), 0)` across `accounts a LEFT JOIN ledger_entries le ON le.account_id = a.id GROUP BY a.id HAVING a.balance_amount != COALESCE(...)`.
